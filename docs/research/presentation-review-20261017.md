## Verdict up front

- **Crash cause.** The proxy queue table filled up, which is the trigger. The 17th proxied `CreateCommandQueue` then threw `presentation-queue-capacity` and hit the plain `fault()` at `presentation.cpp:229`, which turned routing off with no conditions. After that, `route()` and `identity_call()` sent the game's calls on the identity chain to the native methods of that composition chain. That chain is created with Flags 0 and is never presented. The game's next `Present(0, DXGI_PRESENT_ALLOW_TEARING)` returned `DXGI_ERROR_INVALID_CALL`, and `sRender::checkResult` called `MtDebug::abort`, which writes `0xDEADBEEF` to address 0.
- **Agreement.** All six review dimensions found this mechanism independently, and 18 verifier votes confirmed it. Several verifiers read the clean game image and confirmed the game-side chain, including the HRESULT.
- **Fix first.** Never let a call the game makes on the identity chain reach that chain natively. Make every fault record its site, HRESULT, reason and thread. Ship the queue-table fix in the same build, because otherwise every overflow becomes a non-fatal fault that leaves FG stopped and DLSS-G loaded.

## B. Surviving defects in detail

### D1 — Plain `fault()` ends identity routing (Critical)

**Where:** `presentation.cpp:229`, `617/619`, `805/807`, `672`; `identity_chain.hpp:49-60`.

**Confirmed (code).**

The two fault functions disagree:
```cpp
void fault() noexcept { ++stats.faults; accepting.store(false); }                    // 229
void runtime_fault(FaultSite site, HRESULT hr) noexcept { ...
    if (!fault_keeps_routing(contract) && !identity) accepting.store(false); }       // 232-235
```

Once `accepting` is false:
- `route()` returns `forward(s)` at line 617: `if (bypass_depth || ... != identity || !s.accepting.load()) return forward(s);`. For Present that is `original<PresentFn>(s, 4)(self, …)` at line 672, where `self` is the identity chain.
- `identity_call()` does the same at line 805.
- The identity chain has `BufferCount = 2` and no `Flags` (`identity_chain.hpp:56`), and it is created with `CreateSwapChainForComposition` (`presentation.cpp:337`).

The code contradicts its own comment ("faults keep it with an identity chain", line 616) and `fg-live-toggle.md:113` ("faults keep routing; `stop()` ends it"). Nothing ever sets `accepting` back to true; the only `store(true)` is in `install()` at line 960.

**Where I re-opened the code.** Two verifiers noted that the reason-7 path (D3) goes native even with `accepting` kept: `if (!s.proxy_swap) return forward(s);` at lines 619/807. I confirmed this. So "make `fault()` behave like `runtime_fault()`" is not enough. The rule has to be: **never forward a non-bypassed game call on the identity chain to the identity chain itself.** `Presentation::stop()` under AL (`1020`, `1031`) has the same effect but is latent in the shipped FG build.

**Fix.**
1. Split the two meanings of `accepting`:
   - `accepting` keeps meaning "proxy new queues and chains".
   - Identity routing is controlled only by `identity_key`, which only `retire_swap()` and `release_after_shutdown()` clear.
2. Route identity-chain calls by a pure decision: proxy if `proxy_swap` exists; otherwise the native real chain under the synchronous contract (after D3's last resort); otherwise a synthetic answer. Never `self`, unless `bypass_depth` is set (that covers the mod's own calls on the identity chain).
3. `fault(site, hr, why)` records everything and never touches identity routing.
4. `stop()` and `release_after_shutdown()` refuse to end identity routing while the game holds the identity chain.

Details are in section D, group A.

### D2 — Queue proxy table fills up and overflow faults (Critical as shipped, High on its own)

**Where:** `presentation.cpp:166`, `488-510`, `1044`; `continuous_dlaa/runtime.cpp:1387`; `projection_binding/provenance.cpp:341`.

**Confirmed (code).** The gate at line 488 proxies any `CreateCommandQueue` on the game's device unless the calling thread is inside a Bypass or `astera::Internal` scope. Both checks are `thread_local`, so queues created on Streamline/DLSS-G worker threads, overlays and other plugins all count. Each queue takes a slot in `std::array<Queue, 16>` (line 166). The `ComPtr` proxy keeps the native queue alive, and slots are freed only in `release_after_shutdown` (line 1044). On overflow:
```cpp
require(slot != s.queues.end(), "presentation-queue-capacity");   // 495
} catch (...) { s.fault(); }                                        // 507
return original<QueueFn>(s, 0)(self, desc, iid, out);              // 510: the caller still gets a native queue
```
So the fault protects nothing. Only `creation.queue` needs a proxy afterwards (`switch_chain:379`), plus any later chain creation (`516/539/562`).

The alpha DLL compiles two of the mod's own queue creators with no `Internal` scope: `continuous_dlaa/runtime.cpp:1387` and `provenance.cpp:341`, both listed in `CMakeLists.txt` for `mhw_dlss_alpha`. Each runs once and is part of the baseline of 6. `docs/research/live-aspect.md:336-337` ("a full table would no longer end routing under frame generation") is false, because `queue_hook` calls `fault()`, not `runtime_fault()`.

**Confirmed (log, by elimination).** Line 67 reads `faults:1, routing:false, queues:16, fault_site:0, fault_hr:0, identity:true, swapchains:1, switch_reason:1, switch_failures:0`.
- `fault_site:0` rules out `runtime_fault` (every caller passes a nonzero site).
- `switch_reason:1` and `switch_failures:0` rule out line 412.
- `identity:true` rules out lines 529/552/574, because `retire_swap()` clears it (line 265).
- That leaves line 507. `stats.queues` counts only successful proxies (line 502), so 16 means the table was full, and with a full table the capacity check is the only throw possible.

**Hypothesis.** Who created queues 7 to 16 is unknown. Candidates: DLSS-G/NGX threads at 6x dynamic MFG; the Steam overlay (it patches D3D12/DXGI in `core.6652.log`) on SL's pacer thread; or `slDLSSGSetOptions` on the worker, which runs outside any Bypass/Internal scope (`streamline.cpp:197-232`).

**Severity.** Verifiers split 10 high to 8 critical. As shipped it is the trigger of a player crash in normal use, so critical. Once D1 is fixed it becomes a non-fatal fault, but D4 then stops FG and leaves DLSS-G loaded, so it stays high until both are fixed.

**Fix.**
- Overflow is never a fault: count `queue_overflows` and forward natively.
- Stop proxying once the game's chain is adopted: add `&& !s.identity_key.load()` (or `!s.stats.swapchains`) to the gate at line 488.
- Wrap the two discovery queues in `astera::Internal`.
- Record each `queue_hook` entry in a bounded ring (thread, `desc->Type`, caller RVA, proxied/native/overflow) that the alpha also logs.
- Change line 498 to fall through to the original instead of returning the failure (shared with D10).

### D3 — `switch_chain` double failure (High, low likelihood)

**Where:** `presentation.cpp:384`, `391-397`, `408-412`, `705`.

**Confirmed (code).**
- `swap.Reset(); proxy_swap.Reset();` (line 384) runs before anything new is made.
- If `make(frame_generation)` and `make(before)` both fail: `stats.switch_reason = 7; fault(); out = hr; return true;` (line 412).
- `resize_hook` returns that HRESULT from the game's own `ResizeBuffers` (line 705).
- Afterwards `proxy_swap` is null, so identity calls go native (619/807) whatever `accepting` says, and no code path ever makes a window chain again.

**Disputed points, re-checked.**
- *Likelihood.* A failed DLSS-G load alone is absorbed: `make(before)` hits `if (loaded == frame_generation_) return sl::Result::eOk;` (`streamline.cpp:161`) and goes straight to creation. Across 45+ logged switches `switch_waits` is always 0. A double failure therefore needs more than about 1 s of `E_ACCESSDENIED` (a third party holding the old chain), a persistent SL failure, or device removal.
- *Severity.* I keep **high**, not medium. When it does happen, the fail-closed guarantee is lost in exactly the ways the ground rules forbid. The RCA reports that the game's `ResizeBuffers` result goes to `checkResult` (0x239fba0, 0x23a002b, 0x23a0237) and also aborts; that is IDA-confirmed by the RCA but not re-checked in this round.
- *Two sub-claims.* The deadlock sub-claim is refuted (A.3). "Second HRESULT not logged" is partly wrong: `lifecycle_call` stores it as `e.result` (line 465).

**Fix.**
- After both makes fail, create a last-resort native window chain past SL: `Bypass internal(true); original<HwndFn>(*this, 2)(factory.Get(), creation.queue, creation.hwnd, &desc, …)`. Use the `factory` and the native queue, with DLSS-G unloaded. Set `swap = made`, `proxy_swap = nullptr`, `contract = synchronous_native`, `switch_reason = 8`.
- Return `S_OK`. Record both HRESULTs (`switch_last_hr`, `switch_final_hr`) and `fault(FaultSite::switch_chain, hr, …)`.
- Refuse further switches while on the last-resort chain.
- Only if that also fails, enter the synthetic state (D1), and accept that this edge may still freeze or abort.

### D4 — Worker stops supervising after any counted fault (Medium)

**Where:** `presentation_probe.cpp:1392`, `1531-1553`, `1563-1589`, `1660-1665`.

**Confirmed (code).** `if(!stats.routing || stats.faults){stop_reason="presentation";break;}` (line 1392) also exits on a `runtime_fault` that deliberately kept routing. After the loop:
- the worker only calls `arm(false)` (line 1543) and waits 3 s (line 1545);
- `continuous_dlaa::stop()` runs only for `temporal_unhealthy` (lines 1549-1553);
- the loop at 1566-1588 only logs. `sync_generation`, `change_dlss_mode`, `change_dlss_scene` and `apply_reflex_mode` are never called again, and nothing unloads DLSS-G.

After a plain fault, `arm(false)` cannot take effect: `reconcile()` runs only in the routed Present (`game_session.cpp:851-890`), which is why line 64 shows `"off":false, "on":true`. The catch path (1660-1665) does the same after a `require(driver_mode(...))` throw.

**Why it is ordered next to D1.** Once D1 keeps routing after faults, every fault becomes a routing-kept fault. Without this fix, a single queue overflow or transient error then leaves DLSS-G loaded but Off (measured at about 40% fewer fps, `fg-live-toggle.md:12-18`) with dead menu controls.

**Fix.** Split "FG off" from "stop supervising".
- Routing-kept fault: log a `presentation_fault` event, disarm FG, call `request_switch(false)` and `game_resize_request()` so DLSS-G unloads through the normal switch, and **keep the loop running** for DLSS health, menu, Reflex and aspect.
- Routing lost (only possible after D1's synthetic state): reduced loop that polls `temporal::healthy()` and calls `continuous_dlaa::stop()` on a DLSS fault.
- Make the driver-mode checks non-fatal (log, then Reflex off).

### D5 — No backoff after a refused or failed switch (Medium)

**Where:** `presentation_probe.cpp:270-288`; `presentation.cpp:364-370`.

**Confirmed (code).** A refusal (reasons 3, 4, 5) or a restored failure (reason 6) changes `switch_outcomes`. The done branch then logs, sets `fg_loaded` from the unchanged contract, and sets `g={}`. On the next pass `want != fg_loaded` again, so it calls `request_switch` and `game_resize_request()` again. The result is a full game buffer remake (GPU flush, release, `ResizeBuffers`/`ResizeTarget`, `GetBuffer`) and one or more log lines about every 200 ms, with no end. Reason 4 is reachable for anyone who toggles FG or DLSS in exclusive fullscreen, which is a supported mode (`current-state.md:20`); the menu has no fullscreen gate.

**Fix.** Keep `last_refusal{reason, outcome_count}` in the worker.
- Reason 4: do not request again until a `SetFullscreenState` lifecycle event (method 6) arrives.
- Reasons 3, 5 and 6: treat as final for the session, or back off exponentially with a cap.
- Log each refusal reason once, and show "not available in exclusive fullscreen" in the menu.

### D6 — Chain handed over before anyone checks that AL can hook it (Medium)

**Where:** `presentation.cpp:236-249` (`add()` under AL checks only `image_function`), `546-548`; `presentation_probe.cpp:1730-1735`, `749-772`.

**Confirmed.** AL refuses hooks whose target is not in the System32 DXGI/D3D12 modules, and then skips `AL_PHASE_SWAPCHAIN_CREATED`. So `swapchain_chains_missing` is never set. `describe_swap` checks only slots 0, 2 and 12. In tifa-1 (FG off at start) the game ran native and harmless, but the status read "active".

**Hypothesis.** With FG on in the ini and Smooth Motion on, the game would run unrouted on the 6-buffer DLSS-G physical chain (the game-124 index overflow). Not observed.

**Severity.** Medium, by 2 of 3 verifier votes.

**Fix.**
- In `publish()`, before handing anything over, require every routed slot of the new native chain to resolve into System32 `dxgi.dll` (AL's own test). If any slot fails, release the SL chain, unload DLSS-G, return `original<HwndFn>`, and log the module that owns the slot.
- Poll `loader_graphics_running()` from `DEVICE_CREATED` until arming, and show AL's reason on the status page.

### D7 — Diagnostics gaps (Low)

**Confirmed, all in shipped code:**
- (a) `fault()` sets no site or HRESULT. The four `catch(...)` blocks (507/529/552/574) drop `what()`. `FaultSite` has only `none, present, present1, resize, resize1` (`present_result.hpp:27`).
- (b) Queue callers are recorded only when `diagnostic_image` is set (line 221), which only the ownership probe sets.
- (c) `fg_runtime_retained` hard-codes `presentation_routed:true` (`presentation_probe.cpp:1563`; seed line 65 says true, line 67 says `routing:false`). The catch-path `worker_failed` does the same (1662-1663).
- (d) `lifecycle_call` describes `self` under a plain Bypass (467-473), so every `after` shows the identity chain (`buffers:2, flags:0`). `listener.after` takes its format from that chain.
- (e) The scene map is keyed to the real chain at line 287 and never re-keyed in `adopt_identity` or `switch_chain`. Every identity call counts as `foreign` (crash context: `foreign:85371, present_calls:0`).
- (f) The HRESULTs of forwarded Presents (line 672) are never stored.
- (g) `try { describe(); } catch (...) {}` at line 430.
- (h) `game_dlss` state 5 also covers MinHook failures (`startup.cpp:200`).

**Fix.** `fault(site, hr, why)` with new `FaultSite` values (`queue_capacity, queue_proxy, create, switch_chain, stop`), plus `fault_why[64]`, `fault_thread` and `fault_qpc`. Print `snapshot().routing`, `sdk.initialized()` and `temporal::healthy()` instead of literals. Describe `s.native_of(self)` in `lifecycle_call` and pass that format to `listener.after`. Re-key the scene map to the identity chain. Keep a bounded "last non-success HRESULT returned to the host" record (site, method, hr, routed/forwarded). Count describe failures. Add `game_dlss` state 6 ("gates matched, hook failed"). Put a QPC stamp on every event, so the next incident has a timeline.

### D8 — Failed paced Present returns the SDK's HRESULT (Low)

**Where:** `presentation.cpp:656-661, 730-735`; `present_result.hpp:12`.

**Confirmed.** Under `sdk_paced` the hook returns `decision.result`, the SDK's HRESULT. A verifier read the clean image: present12 sends every non-zero result except `0x087A0001` to `checkResult`, which aborts on E_FAIL, E_INVALIDARG, DXGI_ERROR_INVALID_CALL, device-lost codes and others. No Present-site fault has ever been logged. The behaviour is deliberate (comment at `present_result.hpp:7-9`).

**Fix.** Pass device-lost codes through (`DXGI_ERROR_DEVICE_REMOVED`, `_RESET`, `_HUNG`). For anything else, call `runtime_fault` (routing kept), return `S_OK`, and let the D4 worker unload DLSS-G. Update `tests/reflex_present_result_tests.cpp:60-62` to match.

### D9 — Foreign creations disturb the game's chain (Low)

**Where:** `presentation.cpp:523/545/568` (`retire_swap()` before creation), `263-265`, `342-347`, `458-459`, `475-477`.

**Confirmed.** The only gates are `self == s.factory` and `proxy_queue(queue)`. `listener.before` and `listener.after` fire for creations on any factory, so a foreign creation runs `lifecycle_guard` (FG off) and overwrites the HUD-less format.

**Hypothesis.** The trigger needs a tool that uses the game's exact factory (for example via `GetParent`). None is known. See also E: the game's own FilterSwapchain creation at `exe+0x24e75b4` (mentioned in the RCA's fix_risks) has never been checked against this path.

**Fix.** Once `identity_key` is set, route only a creation whose `hwnd == creation.hwnd` and whose caller RVA is in the game image. Forward everything else untouched, with no retire and no fault. Retire only after the new chain has been created successfully. Fire the listener only for the host chain or a routed creation.

### D10 — Failed proxy creation has no native fallback (Low)

**Where:** `presentation.cpp:498` (`*out = nullptr; return hr;`), `277` (`if (FAILED(hr) || !created) return hr;`).

**Confirmed.** A failure inside SL is returned to the game instead of trying the original method. Success with a null chain returns success without writing `*result`. No trigger has been seen in 300 logged creations.

**Fix.** On failure or a null chain: log site and HRESULT, clear `accepting` before any chain exists (which is still fail-closed), and call the original method.

### D11 — `waitable_hook` overwrites `game_waitable` (Low)

**Where:** `presentation.cpp:850-855` and `370`.

**Confirmed.** "The game asks once" is not enforced. A second routed caller replaces `game_waitable`, and every later switch is refused with reason 5. Combined with D5, that becomes a loop. The leak sub-claim is refuted.

**Fix.** Keep the first handle, or adopt the value at `waitable_slot` once it is known. Leave later callers' handles alone.

### D12 — `slSetFeatureLoaded` not serialized with the worker (Low)

**Where:** `presentation.cpp:386` (route mutex only); `presentation_probe.cpp:110` (`sdk_mutex` is file-local).

**Re-checked.** `snapshot()` takes the route mutex (line 963), so iterations after a request block until the switch finishes. The finder's menu scenario cannot happen. What remains is a window in the request iteration (`log_latency` → `slReflexGetState`, at about 1 in 200 switches).

**Fix.** In any iteration where `g.active || stats.switch_pending`, skip the worker's SL calls.

### D13 — NGX startup parks the worker forever (Low)

**Where:** `ngx_startup/worker.cpp:106` and `:111` at HEAD (79e4b1b's 100/105).

**Confirmed (field).** tifa-2 and tifa-4 show `hook_disabled:false, settled:true`. In that state the park protects nothing (seq_cst ordering of `stopping` and `pending`, `startup.cpp:157-159, 214-223`). The PSS adapter made the trigger rarer. Rendering stays native; only the status ("Active/Starting") is wrong.

**Fix.** Make the stream process-lived and `return false` after logging. `prepare()` then throws and `worker_failed` reports the cause. Keep a park only for `!settled`, with the same 30 s drain on the catch path.

### D14 — Missed native init not re-checked (Low)

**Where:** `startup.cpp:182` (only check), `198-199` (decline hook enabled), `205` (init hook enabled).

**Fix.** In the wait loop, fail at once with `native-init-already-observed` when `count==0 && !zero_slots()`. Do **not** swap the hook order; the comment at line 188 explains why.

### D15 — Long blocking waits with no cancellation (Low)

**Where:** `worker.cpp:95-107`.

The 600/300/120 s waits ignore presentation failure. When `before()` rejects, `device` stays null and the 120 s graphics loop cannot succeed. The DX11 part is refuted: AL refuses at `presentation_probe.cpp:1750`.

**Fix.** Skip the graphics loop when `!startup::supported()`. Add a cancellation predicate (presentation side failed, or the adapter is not NVIDIA).

### D16 — `free_wrapper` can return a wrapper with a deleted critical section (Low)

**Where:** `startup.cpp:41-46`.

One `__try` covers both the irreversible `DeleteCriticalSection` and `genericFree`. Never reached in the field (`game_dlss` 2 everywhere).

**Fix.** Guard only the validation reads. After `DeleteCriticalSection`, never return the wrapper; use a distinct state instead.

### D17 — `temporal::receipt()` on an empty name (Low)

**Where:** `temporal_coexistence.cpp:134`.

`name.substr(7)` on the empty name (set only at line 47) throws `out_of_range`. `finish_temporal()` then returns false, `close_sdk()` returns early at `presentation_probe.cpp:459`, and the half-written JSON line runs into the next record.

**Fix.** `name.size() > 7 ? … : null`.

### D18 — Pool readiness check (Nit)

**Where:** `temporal_coexistence.cpp:65`. Require `pb::pool_state().ready`. The `require(pool_ready)` at `presentation_probe.cpp:1131` currently masks this.

## C. Root cause cross-check

### What the findings confirm

Every link in the RCA's chain was found independently by all six dimensions, with 18 confirming votes:
- Plain-fault elimination down to `queue_hook:507`.
- `fault()` clears `accepting` unconditionally (229), while `runtime_fault()` spares the identity case (234).
- Native forwarding to `self` (617/672/805).
- Identity chain created with Flags 0 and 2 buffers (`identity_chain.hpp:49-60`).
- The worker hard-codes `presentation_routed:true` (1563).
- `live-aspect.md:336-337` is false.

### What the findings sharpen

1. **The HRESULT is confirmed at the register level.** I read the AL crash report myself: `rbx=0x143545790`, `r13=0`, `r15=1`, write to 0x0 at `exe+0x21fd0c9`. Three verifiers disassembled the clean image (read-only) and agree with the RCA:
   - `0x23aa1df..0x23aa1ea`: `mov edx,r13d; movzx r8d,r15b; shl r8d,9; call [rax+0x40]`. That is Present (slot 8) with SyncInterval 0 and Flags 0x200 (ALLOW_TEARING).
   - Non-zero results other than `0x087A0001` go to `0x2553ff0`; the return address `0x23aa227` is crash frame 02.
   - There, `cmp ebx,0x887a0001` leads to `call 0x21fd060`; the return address `0x2554119` is frame 01.
   - `0x21fd0c9` is `mov dword ptr [0],0xdeadbeef`.
   - One verifier maps `rbx` to the string `"ERR11 : Invalid DXGI call."` at RVA `0x3545790`.

   So the game's Present returned `DXGI_ERROR_INVALID_CALL`. A failing routed Present would have gone through `runtime_fault` and left `fault_site` nonzero; the log shows 0, so this Present was forwarded natively. Only the DXGI rule itself (tearing flag on a chain created without it) is still unverified at runtime.
2. **Fixing `fault()` alone is not enough.** The `proxy_swap == null` branches (619/807) also forward to the identity chain. The fix must be the routing rule ("never `self`"), not only the fault policy. This also covers D3.
3. **`stop()` and `request_switch()` after a fault are latent, not live,** in the shipped FG build (the worker returns at 1589; `sync_generation` is unreachable after 1392). They still need the same rule, at lower priority.
4. **Timing between fault and abort is unresolved.** Lines 63-67 have no timestamps. Some verifiers argued that "no frame ran after the fault" because `presents − completed` stays at 1113 and `frame_stats` stop counts 3941 = `presents` delta. That is inconclusive: `stats.presents`, `host_frame()` and `completed` are all counted only on routed paths (`presentation.cpp:646, 655`; `live_frames` present hooks). What is certain: the abort happened on the first *native* Present the game made, and every native Present carries ALLOW_TEARING (`r15=1`). Hypothesis: that first frame may have waited up to 1000 ms on the latency waitable first. That waitable belongs to `proxy_swap` (swapped in at 421-424), and nothing presents that chain any more. This fits one verifier's "about a second" estimate from file times. Meanwhile the worker's 3 s FG-off wait and logging ran on another thread.
5. **The queue growth is environment-specific.**
   - Dev: game-126 completed 26 live switches at 6x; game-136 had 8 queues after 6 switches.
   - Baseline is 6 (marie1912-1, flejmzi-2).
   - tifa-6 reached 16 after FG at boot (6x dynamic) plus one unload and one reload.
   - The mod's own unmarked queue creators in the alpha (`runtime.cpp:1387`, `provenance.cpp:341`) run once and belong to the baseline, so they are not the growth.
   - New candidate: `slDLSSGSetOptions` called by the worker outside any Bypass/Internal scope (`streamline.cpp:197-232`), if DLSS-G creates queues there.
   - Proxying foreign queues also feeds them into SL's `slHookCreateCommandQueue`.
6. **Nothing contradicts the RCA.** Its proposed fix B1-B7 matches D1/D2/D3/D4/D7. Two refinements:
   - Choose the synthetic Present result (`S_OK` versus `DXGI_STATUS_OCCLUDED`) only after checking in IDA what present12 and its callers do with OCCLUDED. The RCA's statement that OCCLUDED "requests a chain rebuild" is unverified.
   - The last-resort native chain (D3) should come before any synthetic state.

### Final best explanation of the tifa crash

| # | Step | Status |
|---|---|---|
| 1 | The player had FG on at boot (6x dynamic). Over the session, about 10 command queues beyond the baseline of 6 were created on the game's D3D12 device, outside any Bypass/Internal scope, by an unidentified component. `queue_hook` proxied each one and kept it, filling all 16 slots. | Count confirmed; creator is a hypothesis |
| 2 | The player turned FG off and back on live. Both switches succeeded (`switch_reason 2`, then `1`; `buffers:6`). | Confirmed |
| 3 | Within about one worker poll of the FG-on switch, a 17th gated `CreateCommandQueue` threw `presentation-queue-capacity` (495), was caught at 507, and plain `fault()` set `accepting=false` (229) with no site recorded. | Confirmed by elimination |
| 4 | The game's next Present on its identity chain went through `route()` (617) to the native Present of a Flags-0 composition chain with `ALLOW_TEARING`, returned `DXGI_ERROR_INVALID_CALL`, and the game aborted deliberately (`exe+0x21fd0c9`). | Confirmed (code, crash registers, clean-image disassembly); DXGI rule unverified at runtime |
| 5 | The worker logged `fg_stopped "presentation" off:false`, the literal `presentation_routed:true`, and `presentation_state routing:false` while AL's crash handler ran. | Confirmed |

### Fix to implement first

D1 together with D3's last resort and D7's fault recording. Route every non-bypassed game call on the identity chain to the proxy, to the native real chain, or to a synthetic answer, but never to the identity chain. Faults record site, HRESULT, reason, thread and QPC, and never end identity routing. Ship D2 (queue overflow non-fatal, no proxying after adoption, creator ring log) and D4 (worker keeps supervising and unloads DLSS-G on a routing-kept fault) **in the same build**. Without them, D1 alone turns the tifa-6 trigger into "FG stops, DLSS-G stays loaded, menu dead".

## D. Ordered fix plan

### Group A — Presentation fault fallback and full fault logging (first; one build)

Files: `presentation.cpp` (fault, route, identity_call, switch_chain 408-413, stop/release 1017-1047, present hooks), `present_result.hpp` (FaultSite, pure helpers), `presentation.hpp` (stats), `presentation_probe.cpp` (1392 handling, 1563, presentation_state, fg_switch/heartbeat).

- **A1.** `void fault(FaultSite site, HRESULT hr, const char* why) noexcept`. It increments `faults`, records site, HRESULT, why (a fixed `char[64]` with `strncpy_s`, no allocation, because it runs under `s.mutex`), thread and QPC. It clears `accepting` (new proxies and creations) only. Extend `FaultSite` with `queue_capacity, queue_proxy, create, switch_chain, stop`. Every catch becomes `catch (const std::exception& e) { s.fault(site, E_FAIL, e.what()); } catch (...) { s.fault(site, E_UNEXPECTED, "non-std"); }`.
- **A2.** Identity routing is controlled by `identity_key` only. In `route()` and `identity_call()`:
  ```cpp
  if (const auto id = s.identity_key.load(std::memory_order_acquire)) {
      if (bypass_depth || reinterpret_cast<std::uintptr_t>(self) != id) return forward(s, self); // mod's own calls; other chains
      std::lock_guard lock(s.mutex);
      switch (identity_target(s.proxy_swap != nullptr, s.swap != nullptr, s.contract)) {
      case IdentityTarget::proxy:       /* existing routed path, 620-623 */
      case IdentityTarget::native_real: return forward(s, s.swap.Get());   // synchronous contract only
      case IdentityTarget::synthetic:   return unroutable(s, method);       // never `self`
      }
  }
  ```
  `forward` takes its target explicitly.
